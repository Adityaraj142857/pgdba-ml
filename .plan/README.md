# PGDBA Website — Master Plan

This folder is the single source of truth for the rebuild. Read this file first; it indexes
the rest and records the decisions already locked in, so implementation doesn't drift from
what was agreed.

## Goal (in the user's words)

Rebuild the old WordPress site (now closed) as a free, GitHub-hosted, professional-looking
static site with:

1. A clear, browsable showcase of interview experiences, organized by batch/year.
2. An About PGDBA page.
3. An Admin page where a committee member can upload an Excel file (same shape as the Google
   Forms export in `Excel/`) and have it turn into a new batch of interview experiences on the
   live site — without paying for any hosting/backend.

## Source material already on disk (audited before writing this plan)

- `Interview_Experiences/*.html` — 11 files, one per batch, `2015-17` through `2025-27`.
  These are raw exports from the old WordPress site. **They use four different internal HTML
  structures** across the years (WordPress editor changed hands/formats over a decade). See
  [`02-data-model-and-migration.md`](./02-data-model-and-migration.md) for the exact structure
  of each and the parser plan.
- `Excel/PGDBA Batch 9 Interview Experience (Responses).xlsx` — a raw Google Forms export, 60
  responses × 27 columns (name, college, scores, question categories, tips, etc.). This is the
  **exact shape of file the Admin upload must accept.**
- `images/` — existing PGDBA logo (transparent PNG) and a Facebook banner JPG. To be reused in
  the nav/hero rather than sourcing new brand assets.
- `index.html` (repo root) — a throwaway index auto-generated by whatever tool extracted the
  WordPress export. Not part of the new site; will be replaced by the real homepage.

## Key decisions already made (do not re-litigate without good reason)

| Decision | Choice | Why |
|---|---|---|
| Hosting | GitHub Pages (static only) | User's hard requirement: $0 cost. |
| Framework | **Astro**, static output | Recommended and not objected to. Component reuse, data-driven pages, ships near-zero JS, still builds to plain static files GitHub Pages can serve. |
| Site structure | Exactly **2 public pages**: **About** (also serves as the homepage) and **Interview Experiences** (single page, batch/year switcher — not 11 separate nav items) | User's explicit instruction. |
| Admin | A **3rd, unlinked utility route** (`/admin/`), not in the public nav | Implied by original ask ("admin page"); user did not count it in the "2 pages," so it stays out of primary navigation, reachable by direct URL / a quiet footer link only. |
| Admin publish mechanism | **Direct GitHub publish via a Personal Access Token** entered by the admin and used client-side to call the GitHub REST API | User's explicit choice over (a) manual download+push and (b) raw-file-upload-plus-Action. No backend needed; still $0. |
| Data storage | Interview records as versioned **JSON files in the repo** (`src/data/batches/*.json`), one file per batch, generated by a one-time migration script from the HTML/Excel sources | Keeps the site a pure static build; the JSON *is* the database, and git history *is* the audit log. |

## Open items that need a decision from the user before/soon after Phase 0

These are flagged inline in the relevant docs too, but collected here so nothing slips:

- **GitHub repo name + visibility.** Needs to be a **public** repo for free GitHub Pages
  (private Pages requires a paid GitHub plan). Affects the Astro `base` path config.
- **About-page copy.** What PGDBA actually is (ISI + IIM Calcutta joint program blurb),
  mission/history text — will draft placeholder copy marked `TODO` and ask for real copy or
  sign-off before launch.
- **Custom domain.** The old site used `aspirants.pgdba.ml`. If that domain is still owned,
  it can be pointed at GitHub Pages at no extra cost — out of scope for MVP, revisit in
  Phase 7.
- **Admin publish safety net.** Plan defaults to the CMS opening a **pull request** (not
  pushing straight to `main`) so a human glances at every new batch before it goes live.
  Confirm this is the wanted default vs. direct-to-main.
